## What each scenario proves

- **X01** Savings balance, clean run: Happy path; sensitive balance returned to caller, masked on disk
- **X02** Open sub-account, operator approves: Irreversible commit gated by a single-use approval token
- **X03** Member not found: 'No such member' is an answer, not a crash
- **X04** Deposit below app minimum: App-side validation is a business outcome; caller input was valid
- **X06** Operator declines the commit: Denial is a legitimate answer; nothing committed
- **X07** Known maintenance interstitial: Known dialog dismissed and logged, not surfaced as failure
- **X10** Accounts table rendered late by script: Target appears late; waited within budget
- **X12** Native confirm() guarding the commit: Browser confirm accepted only because it is a known prompt, after operator approval
- **X13** Slow irreversible commit within budget (1.5s): Waited for the commit response; never re-submitted
- **X14** Unknown dialog, human acknowledges: Same live session handed to a human and back after checkpoint verification
- **X15** Session expired, human signs in: Credentials never typed by automation; human re-authenticates on the same session
- **X16** Session expires mid-commit flow, human signs in, operator approves: Handoff and irreversible approval in one run; exactly one commit
- **X17** Compound: interstitial + unknown dialog + session expiry: One recovery plus two separate handoffs, each with its own transition log
- **X20** Persistent HTTP 500: Retry budget spent, then a clear APP_ERROR
- **X22** Ambiguous target (two Savings rows): Stops instead of guessing which row to click
- **X24** Malformed caller input: Rejected before the UI is touched
- **X25** Unknown native alert: Unknown browser prompt dismissed and the run stopped
- **X26** Invisible overlay intercepts clicks: Element found but not clickable: bounded retries, then ACTION_FAILED
- **X27** Input silently truncated by the page: FILL is verified; a truncated value never gets submitted
- **X28** Irreversible commit slower than budget (6s): Committed once, never retried; failure tells the operator to verify in the app
- **X33** Relabelled tenant with overlay (tenant_b): One base artifact reused across tenants via a label/locator overlay
- **X35** Mid-flow redirect off the allowlist: Allowlist checked while waiting on every checkpoint
- **X36** PII echoed on an error page: Evidence and logs stay free of SSN, DOB, email

## Flakiness study

Backend fails 30% of account-detail requests at random (seeded per run). Over 20 fresh runs, the retry budget produced **100% SUCCESS**. Outcomes: {'SUCCESS': 20}. Recoveries used: {'TRANSIENT_APP_ERROR': 4}. Median 0.6s, worst 0.64s. Runs are in `stability/`.

## Determinism check

The clean baseline replayed 10 times produced **1 distinct trace(s)** (bucket, steps executed, and which locator candidate resolved each step). Median 0.59s, worst 0.63s.

## Data handling

PII and secret scan over everything in `evidence/stress/` (seeded SSNs, DOBs, full member ids, the operator password, an email echoed by X36): **clean**.
Sensitive outputs (the balance) are masked in every `result.json` on disk while the caller still receives them. Screenshots mask SSN, date, email, and account-number patterns and password fields.
